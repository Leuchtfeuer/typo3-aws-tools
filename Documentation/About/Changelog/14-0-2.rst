===========================
Version 14.0.2 - 2026/11/30
===========================

* Fix missing slash between CDN host and file path in rewritten file URLs
* Fix ``aws:cf:invalidate`` failing with an ``ArgumentCountError``
* Keep query strings and wildcards in CloudFront invalidation paths
* Invalidate the contents of a folder from the file list, not only the folder object
* Fix invalidation from the file list for storages with an absolute public URL
* Report invalidation paths CloudFront cannot handle instead of failing with an exception
* Rewrite extension resources under ``/_assets/`` (Composer mode) to the CDN
* Load the bundled AWS SDK in classic mode through ``providesPackages``
* Bundle only libraries TYPO3 does not ship and update the AWS SDK to 3.408.0
  (fixes CVE-2026-54133 in the bundled ``mtdowling/jmespath.php``)

.. attention::

   * ``CloudFrontRepository::__construct()`` now requires a second argument of type
     ``InvalidationPathNormalizer``. Code that gets the repository through dependency
     injection is not affected.
   * Invalidation paths containing ``~`` or ``%7E`` are rejected, because CloudFront does not
     support them. The backend module, the CLI command and the file list report such paths.
   * The content replacement has a new default pattern ``30`` for ``"/_assets/``. A pattern
     ``30`` of your own overrides it and should move to another key. Installations that copied
     the default patterns instead of using the extension's TypoScript have to add it themselves.
   * Composer installations now require ``aws/aws-sdk-php`` 3.389 or later.
